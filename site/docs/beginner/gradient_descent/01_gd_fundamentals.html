2  Introduction to Gradient Descent

In this notebook, we will develop the concept of Gradient Descent using linear regression as a concrete example.

We start by generating synthetic data, then define a linear model and a loss function. After that, we implement the optimization algorithm step by step and observe how the model parameters are updated to reduce the loss.

The goal is to build an intuition for optimization-based learning, a concept that will later reappear throughout neural networks and Deep Learning.

def split(x: np.ndarray, y: np.ndarray, val_size=0.2, n=num_gen_values):
  """
  Split x and y into shuffled training and validation sets.
  -> Returns a tuple (x_train, x_val, y_train, y_val, train_idx, val_idx)
  """
  idx = rng.permutation(n)
  n_val = int((n* val_size))
  n_train = n - n_val
  train_idx = idx[:n_train]
  val_idx = idx[n_train:]
  x_train, x_val = x[train_idx], x[val_idx]
  y_train, y_val = y[train_idx], y[val_idx]
  return x_train, x_val, y_train, y_val, train_idx, val_idx

2.5 5. Loss Function

We can see straight away that our randomly initialized function does not represent the data well. To quantify this, we need a loss function.

For the regression problem we wish to solve, we’ll keep it simple by using the mean squared error (MSE). In the summation notation below, our linear model contains a coupling term \(2 \cdot b \cdot w \cdot \sum(x)\). By centering \(x\), the sum becomes 0 and the term is therefore later eliminated.

In this simplified setting, the model has only one input feature. Therefore, the weight \(w\) and the bias \(b\) can also be interpreted as the slope and intercept of a linear function.

\[ \begin{aligned} \displaystyle MSE &= \frac{1}{n} \sum\limits_{i=1}^{n} error_i^2 \\[8pt] &= \frac{1}{n} \sum\limits_{i=1}^{n} (\hat{y}_i - y_i)^2 \\[8pt] &= \frac{1}{n} \sum\limits_{i=1}^{n} (b + w x_i - y_i)^2 \\[8pt] &= \frac{1}{n} \Bigg( \sum\limits_{i=1}^{n} y_i^2 - 2b \sum\limits_{i=1}^{n} y_i - 2w \sum\limits_{i=1}^{n} x_i y_i + b^2 n + {\color{red}{2bw \sum\limits_{i=1}^{n} x_i}} + w^2 \sum\limits_{i=1}^{n} x_i^2 \Bigg) \end{aligned} \]

Next, we put the prediction error over the training dataset into our loss function. Here, we define the error as

\[ \text{error} = \hat{y} - y \]

where \(\hat{y}\) denotes the model prediction and \(y\) denotes the observed target value.

Code 
def mse(y: np.ndarray, y_hat: np.ndarray):
  return (1/len(y)) * np.sum((y_hat-y)**2)

def dmse_dyhat(y: np.ndarray, y_hat: np.ndarray):
  return (2/y.size) * (y_hat-y)

loss = mse(y_train,y_hat)

Looking at the formula, we can already see that large errors have a stronger influence on the MSE because the error term is squared. Plotting the function makes this relationship even more intuitive.

A common misconception is that we can simply explore a dataset, identify outliers, and remove them. In practice, this can quickly lead to wrong assumptions.

This becomes especially clear in biology or medicine. The same blood sample sent to different laboratories can lead to different measured values. These differences may arise from different measurement procedures, insufficient cooling during transport, or intrinsic biological reactions.

A model should therefore be able to handle a certain amount of noise. This does not mean that obvious measurement errors should never be corrected. However, deciding whether a value is noise, a true rare observation, or a measurement error often requires domain knowledge.

Attentive readers may already think about methods such as scaling, transformations, normalization, or more robust loss functions to reduce the influence of large errors. We will revisit these ideas in later chapters.

The second plot shows the derivative of the squared error. While the MSE itself grows quadratically, its derivative grows linearly with the error.

This gives us an important intuition for Gradient Descent. Large errors do not only produce a large loss, they also produce a larger derivative. As a result, these errors can have a strong influence on the optimization process.

Code 
class Calculator():
  def __init__(self, x: np.ndarray, y: np.ndarray, start_axis=0, stop_axis=4):
    try:
      assert x.size == y.size, "Shape missmatch, can cause Problems later"
    except AssertionError as error:
      print(error)
    # Feauture and Target
    self.x = x
    self.y = y
    #Terms from MSE Formula
    self.Syy = np.sum(y**2)
    self.Sxy = np.sum(y * x)
    self.Sxx = np.sum(x**2)
    self.Sx = np.sum(x)
    self.Sy = np.sum(y)
    self.n = len(y)

    #axis
    self.w_axis : np.ndarray | None = None
    self.b_axis : np.ndarray | None = None
    self.w_mesh : np.ndarray | None = None
    self.b_mesh : np.ndarray | None = None
    self.set_mesh(start_axis,stop_axis)

  def mse(self, w = None, b = None, is_mesh=False):
    """
     Compute the MSE for given values of w and b.
     if parameters are a mesh grid:
      is mesh -> true
    """ 
    if w is not None and b is not None:
      w = np.asarray(w)
      b = np.asarray(b)
    elif (w is None) != (b is None):
      raise ValueError("w or b value missing")
    else:
      if not is_mesh:
          w = self.w_axis
          b = self.b_axis
      else:
        w = self.w_mesh
        b = self.b_mesh

    term = (self.Syy - 2*w*self.Sxy - 2*b*self.Sy + w**2 * self.Sxx
            + 2*w*b*self.Sx + self.n*(b**2) )
    mse = term/self.n
    return mse


  def grad_b(self, w, b):
    term = (- 2*self.Sy
            + 2*w*self.Sx + 2*self.n*(b))
    dmse_db = term/self.n
    return dmse_db

  def grad_w(self, w, b):
    term = (- 2*self.Sxy + 2 * w * self.Sxx
            + 2*b*self.Sx )
    dmse_dw = term/self.n
    return dmse_dw

  def set_mesh(self, axis_start: float, axis_stop: float, n=1):
    if n == 1:
      n = self.n
    self.w_axis = np.linspace(axis_start, axis_stop, n)
    self.b_axis = np.linspace(axis_start, axis_stop, n)
    self.w_mesh, self.b_mesh = np.meshgrid(self.w_axis,self.b_axis)

We now examine how the model parameters \(w\) and \(b\) influence the MSE on our training data. The loss surface shows several important properties:

  1. Der Bias Term hat mit unseren Feautures und dem linearen Modell einen schwächeren Einfluss als w -> Additiv vs Multiplikativ. Eine Skalierung, Transformation bsw. der Feautures (x Werte), kann das natürlich ändern.

  2. By adding normally distributed noise, the predicted error is no longer 0 even when using the true generating paramters (true_m, true_b) As a result, the parameters that minimize the empirical MSE on the training data may differ slightly from the true generating parameters. (Analytical calculation at the end)

  3. Consequently, because we added noise to the targets, the true generating parameters no longer produce zero error on the observed training data. Since our model is restricted to a single straight line, it generally cannot pass exactly through all noisy data points. Therefore, the minimum MSE is not zero.

def surface_3d(
    w_mesh: np.ndarray,
    b_mesh: np.ndarray,
    mse: np.ndarray,
    title: str,
    z_lim: float | None = None,
):
  """
  Plot the MSE loss surface in 3d over a mesh grid of weight and bias values

  w_mesh, b_mesh:
      Mesh grids with the weight and bias values
  mse:
      MSE values of the grid
  z_lim:
      Set the 3D z-axis view limits
    """

  fig, ax = plt.subplots(subplot_kw={"projection": "3d"})
  surf = ax.plot_surface(w_mesh, b_mesh, mse, cmap=cm.coolwarm,
                       linewidth=0, antialiased=True,
                       zsort='average')

    ax.set_zlim(z_lim)

  ax.zaxis.set_major_locator(LinearLocator(10))
  ax.set_title(title)
  ax.set_xlabel("w")
  ax.set_ylabel("b")
  return fig, ax

2.6 6. Partial Derivatives and Gradient Descent in 1D

To understand how the parameters \(w\) and \(b\) affect the loss, we first examine them one at a time by fixing one parameter and varying the other.

Left plot: Shows the MSE as a function of one parameter, either \(w\) or \(b\), while the other parameter is held fixed.

Right plot: Shows the corresponding partial derivative, either \(\frac{\partial \mathrm{MSE}}{\partial w}\) or \(\frac{\partial \mathrm{MSE}}{\partial b}\).

We then perform Gradient Descent updates for only one parameter at a time. The update rule for a parameter is

\[ \mathrm{Parameter}_{\mathrm{new}} = \mathrm{Parameter}_{\mathrm{old}} - \alpha \cdot \frac{\partial \mathrm{MSE}}{\partial \mathrm{Parameter}} \]

Here, \(\alpha\) is the learning rate.

The gradient points in the direction of steepest increase. Since we want to minimize the loss, we update in the opposite direction. This is why the update rule contains a minus sign.

Code 
# Decoupling of W and B by centring x at the begin

def viz_pderivate(term: Calculator, axis, fixed_param_value: float, label_x_axis):
  """
  Plot MSE slice and the corresponding partial derivative.

  If label_x_axis is "w", the function varies w and keeps b fixed vice versa.
  """
  lab = input_check(label_x_axis)
  if lab == "w":
    mse = term.mse(axis, fixed_param_value * np.ones_like(axis))
    grad_component = term.grad_w(axis,fixed_param_value)
    title_ = "b"
  else:
    mse = term.mse(fixed_param_value * np.ones_like(axis), axis)
    grad_component = term.grad_b(fixed_param_value,axis)
    title_ = "w"

  fig, (axL, axR) = plt.subplots(1, 2, figsize=(14,4), constrained_layout=True)
  axL.plot(axis, mse, alpha=0.6)
  axL.set_xlabel(lab)
  axL.set_title(f"MSE with fixed ({title_}={fixed_param_value})")
  axL.set_ylabel("MSE")
  axR.plot(axis, grad_component)
  axR.axhline(0, ls="--", lw=1)
  axR.set_xlabel(lab)
  axR.set_ylabel(f"∂MSE/∂{lab}")
  axR.set_title(f"∂MSE/∂{lab}")
  return fig, (axL,axR), fixed_param_value

def viz_update(term: Calculator,
               ax,
               ax2,
               update_trgt,
               fixed_param_value,
               label_x_axis,
               learning_rate = 0.01,
               n_loop=1
               ):

  lab = input_check(label_x_axis)
  x , y, grad_list, step = [], [], [], []
  counter = 0

  for i in range(n_loop):

    if lab == "w":
      mse = term.mse(update_trgt, fixed_param_value)
      grad_component = term.grad_w(update_trgt,fixed_param_value)
    else:
      mse = term.mse(fixed_param_value, update_trgt)
      grad_component = term.grad_b(fixed_param_value,update_trgt)

    x.append(update_trgt)
    y.append(mse)
    grad_list.append(grad_component)

    #plot the start point
    ax.plot(update_trgt, mse, "go", ms=3)

    updadte_step = - (learning_rate * grad_component)
    step.append(updadte_step)

    update_trgt += updadte_step

    #print(f"mse = {y[i]} , grad = {grad_list[i]} , w = {x[i]}")
    if counter >= 1:
      ax.arrow(x[i-1], y[i-1], step[i-1], y[i] - y[i-1], color="red", width=0.02, head_width=0.1,head_length=0.10,)


    counter += 1
  ax2.scatter(x,grad_list, c="red", s=15)

2.7 7. Limitations of a Global Learning Rate and the Simplified Update Rule

The plots above reveal an important limitation: even in this highly simplified setting, using one single global learning rate \(\alpha\) for all parameters can be challenging.

A learning rate that works well for one parameter may be too small or too large for another parameter, especially when the parameters influence the loss on different scales.

2.7.0.1 What we strongly simplified here (the most important points):

1. Dimensionality: Only 2 model parameters instead of thousands to billions

2. Stochasticity: Full gradient computed on all data, no mini-batch noise

3. Non-convexity: Simple convex loss function with one global minimum

  • Deep neural networks are highly non-convex

    • countless local minima
    • Saddle points, where the gradient is zero but not a minimum
    • Flat plateaus with tiny gradients and little progress
    • Narrow valleys and steep cliffs
    • Ill-conditioned loss landscapes

  • A fixed learning rate can get stuck in flat regions or overshoot in steep regions

4. No vanishing or exploding gradients

5. No parameter dependencies: \(w\) and \(b\) are considered separately

Despite these simplifications, we can already observe in our simple 2D case:

  • Different parameters can have different gradient scales
  • A learning rate that works well for \(w\) can be suboptimal for \(b\)
  • The optimal learning rate can change during training

Outlook:

Do not worry if some of these terms are unfamiliar at this point. We will examine them more closely throughout the course. For now, the goal is to build intuition. In the next notebook, we will move from Gradient Descent to Stochastic Gradient Descent and other optimizers, and we will also look at strategies for adapting the learning rate.

2.8 8. Chain Rule

Using the chain rule, we can compute the gradient of the MSE with respect to the model parameters. We will discuss this idea in much more detail in the Backpropagation notebook, once we move on to deep neural networks.

\[ \nabla_{w,b}\,\mathrm{MSE} = \begin{bmatrix} \dfrac{\partial \mathrm{MSE}}{\partial w} \\ \dfrac{\partial \mathrm{MSE}}{\partial b} \end{bmatrix} = \frac{2}{n} \sum_{i=1}^{n} \begin{bmatrix} x_i(\hat{y}_i - y_i) \\ (\hat{y}_i - y_i) \end{bmatrix} \]

\[ \frac{\partial \mathrm{MSE}}{\partial w} = \sum_{i=1}^{n} \frac{\partial \mathrm{MSE}}{\partial \hat{y}_i} \frac{\partial \hat{y}_i}{\partial w} = \frac{2}{n} \sum_{i=1}^{n} x_i(\hat{y}_i - y_i) \]

\[ \frac{\partial \mathrm{MSE}}{\partial b} = \sum_{i=1}^{n} \frac{\partial \mathrm{MSE}}{\partial \hat{y}_i} \frac{\partial \hat{y}_i}{\partial b} = \frac{2}{n} \sum_{i=1}^{n} (\hat{y}_i - y_i) \]

Code 
# With Chain rule C/z * z/w (or b)
def m_grad(x,y,y_hat):
  return (2/len(y)) * ((y_hat-y) * x).sum()

def b_grad(y,y_hat):
  return 2 * (y_hat-y).mean()

lr = 0.01 # or lr * 2 and simplify the derivative of MSE 1/2n(...)

def update_target(target, gradient, lr=lr):
  new_target = target - lr * gradient
  return new_target

2.9 9. Training

We train the model for 400 epochs. The core idea is:

  1. Create a prediction using the current parameters.
  2. Compute the training loss by comparing the prediction with the true values from the training set.
  3. Compute the two components of the gradient.
  4. Update \(w\) and \(b\) using a learning rate \(\alpha = 0.01\).
  5. Validate the model on the validation set using the updated parameters.
Code 
epoch = 400
train_loss, val_loss , pred_history = [], [], []
w_path, b_path = [], []

def train_step(x_train,y_train,w,b):
  y_hat = predict(x_train,w,b)
  mg = m_grad(x_train,y_train,y_hat)
  bg = b_grad(y_train,y_hat)
  w = update_target(w,mg)
  b = update_target(b,bg)
  y_hat_updated = predict(x_train,w,b)
  loss = mse(y_train,y_hat_updated)
  pred_history.append(y_hat_updated)
  w_path.append(w)
  b_path.append(b)
  return w,b,loss

def validate(x_val,y_val,w,b):
  y_hat_val = predict(x_val, w, b)
  v_loss = mse(y_val, y_hat_val)
  return v_loss


for e in range(1,epoch+1):
  w,b,t_loss = train_step(x_train,y_train,w,b)
  v_loss = validate(x_val,y_val,w,b)
  train_loss.append(t_loss)
  val_loss.append(v_loss)

We can see that the model initially converges quickly toward the optimum. After that, the curve visibly flattens, because the gradients become very small near the minimum and further improvements happen only slowly, this interpretation is specific to our simple two-parameter MSE example.

The remaining error is therefore not mainly caused by insufficient training. Instead, it is largely due to irreducible noise in the data. Training for more epochs would therefore not meaningfully reduce the loss any further.

2.10.0.1 Note

When training deep neural networks, computational cost can grow quickly, so long training runs can become expensive. For a synthetically generated dataset like the one in our example, this is not a major issue. In real-world scenarios, however, it often matters.

A common strategy for reducing unnecessary training time is Early Stopping. If the validation loss does not improve by more than a predefined threshold for several consecutive epochs, training is stopped automatically. This saves computation time and avoids optimization steps that no longer improve generalization.

The effect of Early Stopping on certain training dynamics, such as Grokking, will be discussed separately later.

2.11 11. Visualizing the Gradient Norm

The gradient is a vector that points in the direction of steepest increase at each point \((w, b)\). In our case, it has two components: the partial derivative with respect to \(w\) and the partial derivative with respect to \(b\).

This structure makes direct 3D visualisation difficult. We would have to show two separate arrows or a vector arrow at each point, which would quickly become confusing. Of course, there are also ways to represent loss landscapes in simplified form within n-dimensional parameter spaces, but that would go beyond the scope of our discussion here.

Instead, we visualize the gradient norm, which is the length of the gradient vector:

\[ \left\lVert \nabla \mathrm{MSE} \right\rVert = \sqrt{ \left(\frac{\partial \mathrm{MSE}}{\partial w}\right)^2 + \left(\frac{\partial \mathrm{MSE}}{\partial b}\right)^2 } \]

The norm is a single scalar value that provides us with important information. It measures how much the loss function changes at this point, regardless of the specific direction. A large norm indicates that we are in a steep region, regardless of whether the slope comes from \(w\), from \(b\), or from both. A small norm, on the other hand, indicates a flat region, and at minima, maxima and saddle points, the norm becomes zero.

The gradient norm directly determines the step size in the gradient descent update in combination with the learning rate. In regions with a large norm (steep slopes), this simplified algorithm takes large steps, whilst in flat regions it takes only small steps. We can see this from the visualisation.

This intuition will be important later when we train neural networks. The main idea remains the same: compute predictions, measure the loss, compute gradients, and update the parameters. Since the model in this notebook is only a simple linear model, there is also an analytical solution. Instead of finding the parameters iteratively with Gradient Descent, we can compute the optimal linear regression parameters directly using the method of least squares.

2.13 13. Linear Model and Design Matrix

We consider a linear regression model. Linear in this context does not mean a straight line for us, but refers to the parameter space \(w\). The feature space \(X\) can be nonlinear, for example \([1, x, x^2]\).

Since in our case we want to approximate a linear equation,

\[ f(x) = m \cdot x + b, \]

we move in a two-dimensional parameter space:

\[ w_1 \cdot x + w_0 \cdot 1. \]

Of course, we could extend this parameter space, but there has to be meaningful semantics behind it. For example,

\[ w_2 \cdot x_1 + w_1 \cdot x_1 + w_0 \cdot 1 \]

is nothing more than

\[ (w_2 + w_1) \cdot x_1 + w_0 \cdot 1. \]

This is problematic because we have now created a linear dependency in the design matrix. As a result, \(\Phi^\top \Phi\) is no longer guaranteed to be invertible, because

\[ \operatorname{rank}(\Phi) < D+1. \]

The system of equations would then have infinitely many solutions, and the following inverse-based equation could no longer be used directly. We would have to choose another approach.

There are ways to extend the feature space in a meaningful way through feature engineering. However, we will look at this in a later chapter.

\[ \hat{y} = f(x; w) = w_0 + w_1 x_1 + \dots + w_D x_D = w^\top \phi(x) \]

with

\[ \phi(x) = \begin{pmatrix} 1 \\ x_1 \\ \vdots \\ x_D \end{pmatrix}, \quad w = \begin{pmatrix} w_0 \\ w_1 \\ \vdots \\ w_D \end{pmatrix} \]

For \(n\) data points, we combine all feature vectors into a design matrix \(\Phi\):

\[ \Phi = \begin{pmatrix} \phi(x_1)^T \\ \phi(x_2)^T \\ \vdots \\ \phi(x_n)^T \end{pmatrix} \in \mathbb{R}^{n \times (D+1)} \]

Then we can write compactly:

\[ \hat{y} = \Phi w \]

2.14 14. Error Function (SSE/MSE) and Normal Equations

We define the sum of squared errors (SSE) as

\[ O(w) = \sum_{i=1}^n (y_i - w^\top \phi(x_i))^2 = | y - \Phi w |^2 = (y - \Phi w)^\top (y - \Phi w) \]

As we can easily see, the MSE is nothing more than a scaled version of the SSE by a factor of \(\frac{1}{n}\). Since this scaling does not change the location of the minimum, we can refer back to the loss surface from the previous section. There, we can see that the loss function is convex, which is the key property that makes the following analytical approach possible.

\[ \tilde{O}(w) = \frac{1}{2} | y - \Phi w |^2. \]

The factor \(\frac{1}{2}\) does not change the minimum. It only simplifies the derivative.

Taking the derivative with respect to \(w\) gives

\[ \nabla_w \tilde{O}(w) = \Phi^\top \Phi w - \Phi^\top y. \]

At the minimum, we set the gradient equal to zero:

\[ \nabla_w \tilde{O}(w) = 0. \]

This gives

\[ \Phi^\top \Phi w = \Phi^\top y. \]

These are the normal equations. If \(\Phi^\top \Phi\) is invertible, we can solve for \(w\) directly:

\[ \hat{w} = (\Phi^\top \Phi)^{-1} \Phi^\top y. \]
